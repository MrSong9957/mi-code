# 修复滚动失效 + 选区不精准回归（全屏选区重构引入）

## 根因（已诊断确认）

| 问题 | 根因 |
|---|---|
| 1a 滚轮滚不动 | `scrolledAway` 是 ref（不触发重渲染），ScrollBox 自动跟随 effect 依赖 `[messages.length, maxScroll]` 不含 scrolledAway/scrollTop |
| 1b 滚动被拽回底部 | 流式时 messages 频繁变化 → effect 反复触发 `onScrollTopChange(() => maxScroll)`，把用户滚上去的位置拽回底部 |
| 1c 无键盘翻页 | use-input-handler 明确忽略 PageUp/PageDown |
| 2a 多行消息选区错位 | `sliceVisible` 按消息切片，`globalRow = LOGO_ROWS + scrollTop + i`（i 消息索引）+ MessageRow `globalRow + i`（i 行索引）→ 多行消息行号撞车 |
| 2b Footer 区选区错位 | `inputRowY` 算 `Math.min(messages.length, ...)` 按消息数而非行数 |

核心矛盾：两套坐标模型——scroll-state（按消息）vs row-text-map（按行）。

## 修复方案（5 个 Task）

### Task 1：行列表展开工具 `flatten-messages.ts`（新纯逻辑）

新建 `src/tui/selection/flatten-messages.ts`：
```ts
interface FlatLine { messageUuid: string; lineIndex: number; line: FormattedLine; }
function flattenMessages(messages: TuiMessage[]): FlatLine[]
```
把已固化消息的 lines 拉平成行数组（跳过流式块的 finalized=false）。

配测试：单行消息、多行消息、流式块跳过、空。

### Task 2：ScrollBox 改按行切片 + 行级 globalRow

`src/tui/components/ScrollBox.tsx`：
- 用 `flattenMessages(messages)` 得到 FlatLine[]
- `computeScrollState({ total: flatLines.length, visibleRows, scrollTop })` —— total 是行数
- `sliceVisible(flatLines, state)` 切片可见行
- 渲染：每行一个 `SelectionText`（不再用 MessageRow 包整条消息），globalRow = `LOGO_ROWS + state.scrollTop + i`（i 是**行**索引，不再撞车）
- 流式块（最后一条未固化 assistant）特殊处理：在可见行末尾渲染 StreamingMarkdown（占可变行，不参与行号——但行号映射要在 rowTextMap 里对齐，见 Task 3）

注意：ScrollBox 不再渲染 MessageRow，直接渲染每行的 SelectionText。MessageRow 退化为只处理流式块的包装（或合并进 ScrollBox）。简化：ScrollBox 直接渲染已固化行 + 流式块。

### Task 3：rowTextMap + inputRowY 按行算

- `src/tui/selection/row-text-map.ts`：`messageLineText` 的 `flatRow = row - LOGO_ROWS + scrollTop` 现在正确（scrollTop 已是行索引）。保持按行累计 lines.length 的逻辑。
- `src/tui/App.tsx`：`scrollboxRenderedRows` 改为可见行的**行数和**（`Math.min(flatLineCount, visibleRows)`）；`inputRowY` 同步按行算。ConnectedApp 也要同步改 footerRows/inputRowY 计算（用 flatLineCount）。
- `src/tui/ConnectedApp.tsx`：inputRowY 计算用 flatLineCount 而非 messages.length。

### Task 4：修滚动状态 + 自动跟随

`src/tui/ConnectedApp.tsx`：
- `scrolledAwayRef` 改为 `useState`（让变化触发重渲染）
- `effectiveScrollTop` 逻辑保留（scrolledAway=false 时钉到 maxScroll）
- `handleWheel`/`maybeStartAutoScroll` 改 setState 时同步设 scrolledAway（现在用 setScrolledAway）
- **删除 ScrollBox 的自动跟随 effect**（移到 ConnectedApp，在 render 时同步算 effectiveScrollTop，不再用 effect）

`src/tui/components/ScrollBox.tsx`：
- 删除自动跟随 effect（由 ConnectedApp 的 effectiveScrollTop 接管）
- 删除 `scrolledAway`/`onScrollTopChange` props（不再需要——ScrollBox 纯受控，scrollTop 父级算好传入）

`src/tui/App.tsx`：删 scrolledAway/onScrollTopChange props 透传。

### Task 5：键盘 PageUp/PageDown

`src/tui/input/use-input-handler.ts`：
- 加 `key.pageUp`/`key.pageDown` 分支
- 新增 `onPageScroll?: (delta: number) => void` 回调参数
- ConnectedApp 实现 onPageScroll：调 setScrollTop + setScrolledAway(true)

`src/tui/ConnectedApp.tsx` + `bootstrap.tsx`：透传 onPageScroll。

## 风险

- MessageRow 退化为流式专用——若其它地方（测试）引用 MessageRow 渲染已固化消息会断。grep 确认调用方。
- ScrollBox 渲染已固化行用 SelectionText（复用），流式块用 StreamingMarkdown——两条路径。
- 流式块占可变行数，行号映射在流式期间可能瞬时错位（接受，流式块不可选）。
- scroll-state.ts 不改（已是泛型，total 传行数即可）。
