下面针对清单上的每个高风险功能，逐个设计测试用例。**核心原则：验证数据变化和状态迁移，而不是看接口有没有返回成功。** 每个功能都标注"关键验证点"——这是区分真测试和假测试的分水岭。

## 🔴 P0：必须重点测试

### 1. 权限四步管道 `PermissionChecker.check()`

| 类型 | 输入 | **关键验证点（数据变化）** |
|------|------|--------------------------|
| **正常** | build 模式，只读工具 read_file | 返回 `allow`；**且下游 executor 真的被调用了**（用 spy.count 验证，不是看返回字符串） |
| **正常** | plan 模式，run_bash 写命令 `git commit` | 返回 `deny`；**且 registry.execute 调用次数为 0**——工具根本没跑 |
| **正常** | 闸门优先级：危险命令 + 用户 allow 规则同时命中 | **必须 deny**（闸门1 > 闸门4）。验证规则不会"开后门"放行危险命令 |
| **边界** | deny 规则用 glob `write_*`，工具是 `write_file` | **命中**（验证 `*` 跨字符匹配）；工具是 `read_file` 时**不命中** |
| **边界** | `input.command` 为 `''`（空串）、`undefined`、`null` | 不抛异常，按"无命令"处理走默认分支（不误判为危险） |
| **边界** | workdir 末尾带/不带分隔符（`/a/b` vs `/a/b/`） | 越界判定结果**一致**（这正好是 safePath 的 bug 来源，要对照验证） |
| **异常** | 未知工具名 `'foobar'` | 不在 READ_ONLY 也不在 WRITE_TOOLS → 走默认 ask（不崩溃） |
| **异常** | `input` 不是对象、是数组、含循环引用 | 不抛异常，安全降级 |

> ⚠️ **假测试陷阱**：只断言 `decision.behavior === 'deny'` 不够。必须验证**下游 executor 的调用次数=0**，否则权限层"说 deny 了"但执行层照样跑，等于没拦。

### 2. 危险命令黑名单 `isDangerousBash()` / `isWriteBash()`

| 类型 | 输入 | **关键验证点** |
|------|------|----------------|
| **正常** | 31 种写命令逐个测（mkdir/rm/git commit/npm install/sed -i） | 每个都返回 true（数据驱动，**不是写一个循环 expect**） |
| **正常** | 19 种只读命令（ls/cat/grep/git log/git status） | 都返回 false，**不误报** |
| **边界** | `rm -rf`（同时是危险也是写） | **双重命中**——`isDangerousBash` 和 `isWriteBash` 都返回 true。验证两者**不是互斥**的 |
| **边界** | `mkdir`（仅写不危险） | `isWriteBash=true` 但 `isDangerousBash=false`——验证区分度 |
| **边界** | 命令含大小写变体 `RM -RF`、`Sudo` | 当前正则区分大小写 → **应放行**（记录这是已知弱点，黑客可绕过） |
| **异常** | 命令注入变体：`ls; rm -rf /`、`ls && sudo x`、`ls \| rm -rf` | **必须命中**——验证黑名单是子串匹配而非整串匹配 |
| **异常** | fork bomb `:(){ :\|:& };` | 命中。这是资源耗尽攻击，漏判=机器卡死 |

> 关键：黑名单是**全项目唯一来源**（permission + hooks 共享），任何模式漂移都是安全事故。测试要断言"两个消费者用的是同一个数组引用或行为一致"。

### 3. 路径沙箱 `safePath()` / `isPathOutsideWorkspace()`

| 类型 | 输入 | **关键验证点（文件系统状态）** |
|------|------|------------------------------|
| **正常** | 内部相对路径 `foo/bar.txt` | 返回绝对路径 = `join(workdir, 'foo/bar.txt')`；**且该路径确实在 workdir 内**（用 `startsWith(workdir + sep)` 二次验证） |
| **正常** | `..` 穿越 `../evil.txt` | 抛错；**且通过 write_file 走通时，工作区外文件确实没被创建**（造一个 tmpdir，跑完后 `existsSync(outsideFile) === false`） |
| **边界** | 前缀碰撞 `workdir + '_evil'/x.txt` | **这是已知 bug**：safePath 放行了，isPathOutsideWorkspace 正确拒绝。对照验证两者行为分歧 |
| **边界** | Windows 盘符 `C:\`、UNC 路径 `\\server\share` | resolve 后跨平台行为一致 |
| **边界** | 符号链接指向工作区外 | 当前实现**不解析 symlink**（只做字面 startsWith）→ 漏判。记录这是弱点 |
| **异常** | 空字符串 `''`、纯 `.`、纯 `..` | resolve 后的判定结果明确（`''` → workdir 本身 → 内部；`..` → 父目录 → 外部） |

> 最关键的验证：**不要只看 safePath 抛不抛错，要看磁盘上工作区外的文件到底有没有被写出来。** 真实跑一遍 write_file，检查 `existsSync`。

### 4. 后台 shell 执行 `BackgroundManager`

| 类型 | 输入 | **关键验证点（进程 + 文件状态）** |
|------|------|--------------------------------|
| **正常** | `echo hello` | ① 立即返回 task_id（elapsed < 100ms）；② **log 文件内容含 'hello'**（readFileSync 验证，不是看返回值）；③ 进程结束后从 running 列表消失 |
| **正常** | 长任务 `timeout 10` | drainNotifications 返回 running 状态；**10 秒后状态变 timeout/completed** |
| **边界** | 输出超 500 字符 | **log 文件完整**，但 preview **被截断到 500**（验证截断逻辑，不是全量） |
| **边界** | 僵尸进程：有输出但超时 vs 无输出超时 | 前者**不误杀**（仍在 running），后者**标记 timeout**。这是并发临界——误杀会丢正在跑的合法任务 |
| **边界** | 并发起 10 个后台任务 | 每个 task_id 唯一；log 文件互不串扰（**读每个 log 内容对应自己的命令**） |
| **异常** | 不存在的命令 `nonexistent-cmd-xyz` | 状态标 error；log 含错误信息；**进程不留僵尸** |
| **异常** | `killAll()` 后 | **所有子进程真实死亡**（用 `ps` 或进程列表验证，不是看返回值）；`.runtime-tasks/` 状态落盘 |

> ⚠️ 这个功能的测试必须用**真实子进程**（echo/timeout），不能 mock spawn——mock 测不到僵尸、测不到 kill 是否真的发信号。现有测试做得对。

### 5. 文件写/编辑 `write_file` / `edit_file`

| 类型 | 输入 | **关键验证点（磁盘内容）** |
|------|------|--------------------------|
| **正常** | write_file 新文件 | **readFileSync 读回内容 == 写入内容**（字节级，含 UTF-8 中文/emoji） |
| **正常** | write_file 覆盖已有文件 | **旧内容完全消失**，新内容写入（验证是 truncate+write 不是 append） |
| **正常** | edit_file：old_text 精确匹配 | **只有匹配段被替换**，其余内容原样保留；**文件 mtime 更新** |
| **边界** | edit_file：old_text 在文件中出现 2 次 | **当前实现只替换第一个还是全部？** 验证实际行为（这是数据正确性关键） |
| **边界** | 父目录不存在 | **自动 mkdirSync recursive**（验证目录被创建，不是报错） |
| **边界** | 写入超大文件（10MB） | 不截断，内容完整；不 OOM |
| **异常** | edit_file：old_text 不存在 | **原文件保持不动**（这是最重要的保护——不能因为找不到就清空文件）；返回错误 |
| **异常** | path 指向目录而非文件 | 报错，不把目录当文件写 |
| **异常** | 路径逃逸 | 沙箱拦截，工作区外文件**不存在** |

> **假测试陷阱**：只看 write_file 返回 "success" 不够。必须 readFileSync 读回内容验证。edit_file 找不到 old_text 时，**必须验证原文件内容没变**（很多人测了"返回 Error"但没测"文件没被动过"）。

### 6. worktree 删除 `remove()` / `safeRemove()`

| 类型 | 输入 | **关键验证点（文件系统 + git 状态）** |
|------|------|--------------------------------------|
| **正常** | safeRemove 干净 worktree | 目录删除（existsSync=false）；`.worktrees/index.json` 中记录消失；events.jsonl 追加 removed 事件 |
| **正常** | safeRemove 脏 worktree（discardChanges=false） | 返回 Refused；**未提交文件仍在**（existsSync=true）；**git worktree 列表中仍存在** |
| **正常** | safeRemove 脏 worktree（discardChanges=true） | 强制删除；未提交文件**丢失**（验证 `--force` 真的覆盖了） |
| **边界** | remove（非 safe 版本）删脏 worktree | **git 自身保护**会抛错（Command failed）——验证这个回退保护，但错误信息不友好（缺口） |
| **边界** | worktree 名含特殊字符 `../`、`; rm -rf` | **SAFE_NAME_RE 拦截**（命令注入防护）；不执行恶意命令 |
| **异常** | 删除不存在的 worktree 名 | 抛错 "not found"，不影响其他 worktree |
| **异常** | recover 从磁盘重建 | 进程崩溃后重启，records 与磁盘 index.json **完全一致**（数量、字段） |

> 关键验证：删除后用 `git worktree list` 真实跑一遍，确认 git 视角下也删了，不是只删了我们的台账。

### 11. LLM 重试/熔断 `recovery.ts`

| 类型 | 输入 | **关键验证点（状态变化）** |
|------|------|---------------------------|
| **正常** | max_tokens 错误 | **state.maxTokens 被调大**（验证数值变化，不是看返回）；messages 追加续写消息 |
| **正常** | prompt_too_long 错误 | **compactFn 被调用**（spy.count=1）；messages 数组**变短**（压缩生效） |
| **正常** | 429 错误 | **模型降级**为 haiku；**backoff sleep 被调用**且延迟在 [0, 2000)（Full Jitter 范围） |
| **边界** | 第二次 prompt_too_long | **放弃**（不再无限压缩）；返回 abort 状态 |
| **边界** | 重试次数达 MAX_RETRY_LIMIT=3 | **停止重试**，抛最终错误；fn 调用次数=4（1 初始+3 重试） |
| **异常** | 未知错误类型 | 不套用任何恢复策略，直接 abort（不瞎重试） |
| **异常** | backoff 间隔验证 | 第 n 次重试的延迟 ≤ `min(cap, base * 2^n)`（验证 Full Jitter 上界） |

> ⚠️ 这是**资金防线**。假测试只看"重试成功了"，真测试要验证：① 模型真的降级了吗（抓 API 调用参数）② backoff 间隔对吗（抓 sleep 参数）③ 重试次数没超上限（抓调用次数）。重试失控=账单爆炸。

## 🎯 总结：真测试 vs 假测试的分水岭

整个清单里反复出现的**核心验证原则**：

| ❌ 假测试（只看接口） | ✅ 真测试（看数据变化） |
|---------------------|----------------------|
| `expect(result.success).toBe(true)` | `readFileSync(path) === 写入内容` |
| `expect(decision.behavior).toBe('deny')` | `spy.count === 0`（工具真没跑） |
| `expect(manager.remove()).not.toThrow()` | `existsSync(dir) === false`（目录真没了） |
