# i18n Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

## Goal

为 MiCode 增加首版 `zh-CN` / `en-US` 用户体验语言支持：默认固定使用 `zh-CN`，支持启动参数临时覆盖、ConfigStore 持久化和 `/language` 运行时切换；让 React/Ink、普通 TypeScript 命令执行器及展示层共享同一个 Zustand vanilla `LanguageStore`；将批准 spec 规定的用户可见静态文本迁移到 locale 资源，同时保持命令、工具、路径、协议字段、代码、模型 ID、Provider 和用户原始输入不变。

## Architecture

- `src/locale/` 是轻量 locale 模块：`Language`、支持语言列表、canonical `zh-CN` 资源 schema、`en-US` 资源、动态 translator、Zustand vanilla `LanguageStore` 和 React `LocaleProvider/useLocale()`。
- `LanguageStore` 是唯一 runtime language 状态。Context 只订阅它，不保存第二份语言状态。
- ConfigStore 只持久化 `language`；CLI 初始化值按 `validCliLanguage ?? validConfigLanguage ?? 'zh-CN'` 解析。
- 普通 TypeScript 通过绑定同一 `LanguageStore` 的 translator 在调用时读取当前语言；所有 render/调用都生成即时文本，不缓存依赖当前语言的最终字符串。
- `zh-CN` 资源是 canonical shape；`en-US` 必须满足同一 shape。简单 `{param}` 插值保留缺失参数原占位符，不实现 ICU/plural engine。
- `/language` handler 直接执行 validate → ConfigStore 持久化 → `LanguageStore.setLanguage()`；不创建 `LanguageController`。
- 权限流程使用稳定 decision ID/option ID 传递语义，显示 label 仅供用户阅读。任何业务逻辑不得依赖翻译字符串。

## Tech Stack

- 现有 TypeScript strict/ESM、Zustand vanilla、React/Ink、Vitest。
- 复用现有 ConfigStore、ThemeStore/Provider、bootstrap、commands executor、BlockPipeline 和测试工具。
- 不引入第三方 i18n 库，不修改 `system.md` / `planner.md` 的完整内容。

## Global Constraints

- 不读取 OS locale、`LANG` 或 `LC_ALL`。
- `--language <unsupported>` 是显式 CLI 输入错误：显示支持的 `zh-CN` / `en-US`，非零退出；不得回退到 ConfigStore 或 `zh-CN`。
- 非法 ConfigStore.language 视为未配置；旧配置缺少 language 时仅在内存中使用 `zh-CN`，不得因启动自动改写 `config.json`。
- `/language` 无参数只显示当前 effective language 和支持列表；不写 ConfigStore、不更新 LanguageStore，反馈使用当前语言。
- `/language <lang>` 校验或持久化失败时保留旧 runtime language并使用旧语言报错；持久化成功后才更新 store，成功反馈使用新语言。
- 当前正在执行的 Agent 请求保留原 system prompt；下一轮请求读取最新 runtimeLanguage。
- 不重写已有 transcript；用户原始输入、Agent 原文、工具输出、代码、diff、路径、模型 ID、Provider、命令名、工具名、参数和协议字段不翻译。
- 生产缺失翻译按“当前语言 → `zh-CN` → `‹missing translation: key›`”回退，不因单个 key 缺失使 CLI/TUI 崩溃；开发/测试必须暴露漏翻译。
- 每个可测试功能按 RED → GREEN → 最小整理 → 相关测试命令验证；完成一个 Task 后再进入下一个 Task。
