# i18n Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the approved `zh-CN`/`en-US` i18n behavior to MiCode while preserving command, protocol, permission, transcript, raw-agent, raw-tool and user-input semantics.

**Architecture:** `src/index.ts` resolves startup language and creates the sole `LanguageStore` instance. It creates one `Translator` bound to that store and passes the same store/translator to `bootstrap({ languageStore, translator })`, command context, pipeline/presentation constructors and the per-turn Agent prompt builder. React `LocaleProvider` subscribes to that store but does not own language state; ConfigStore persists language only.

**Tech Stack:** Existing strict TypeScript/ESM, Zustand vanilla stores, React/Ink, Vitest, ConfigStore, command executor and BlockPipeline. No third-party i18n library and no `LanguageController`.

## Global Constraints

- Supported languages are exactly `zh-CN` and `en-US`; default is exactly `zh-CN`.
- Startup initialization is `validCliLanguage ?? validConfigLanguage ?? 'zh-CN'`; CLI override is temporary and is not persisted.
- `src/index.ts` creates the only `LanguageStore`; `bootstrap` never calls `createLanguageStore` and never returns a language store.
- Invalid ConfigStore language is treated as unconfigured; loading legacy or invalid config never writes `config.json`.
- Invalid explicit `--language` prints supported languages and exits nonzero without falling through to ConfigStore/default.
- `/language` with no argument reads current effective language/support list only; it performs no ConfigStore write and no LanguageStore update.
- `/language <lang>` performs validate → ConfigStore persistence → LanguageStore update → success feedback. Validation/persistence failure leaves the old runtime language and uses the old translator.
- Existing Agent requests keep their already-built prompt; the next request reads the current LanguageStore.
- Do not translate commands, tool names, parameters, paths, protocol fields, code, diffs, model IDs, Provider names, user input, Agent original text or tool output.
- Runtime fallback is current language → `zh-CN` → `‹missing translation: key›`; translator calls do not throw for a missing key or parameter. A missing parameter preserves `{param}`.
- `zh-CN` is the canonical resource shape. TypeScript proves missing/extra resource keys and node structure; placeholder-name equality is tested once. Do not add a duplicate runtime key-set comparison.
- Simple `{param}` interpolation is the only interpolation engine. English count variants use explicit resource keys such as `.one` and `.other`.
- Stable permission decision/option IDs are independent from display labels. Permission business logic never compares translated labels.
- `system.md` and `planner.md` are not fully translated; each request only appends the current locale’s response-language preference resource.
- Every Task has one RED → GREEN → focused verification → commit cycle. The implementation worker must run the commands and observe the stated result before advancing.
