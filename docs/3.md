## 修正后的 Bug 描述

**标题**：界面布局严重错位 —— Logo 显示不完整，元素间距异常，Footer 脱离文档流

**复现路径**：
1. 终端窗口约 220 列
2. 执行 `node dist\index.js`
3. 观察初始界面

**期望行为**：
```
 ▐▛███▜▌   MiCode v1.0.0      ← Logo 完整显示（多行 ASCII art，当前仅显示底部 1/3）
[Hook] Session started at ...  ← Hook 紧随 Logo
(消息区)
───────────────────────────    ← 上边框在 Hook 之后
❯                              ← 输入框
───────────────────────────    ← 下边框
build │ mimo-v2.5-pro │ ...   ← 状态栏
```
无消息时所有元素纵向紧凑排列，无多余空白。

**实际行为**：
```
 ▐▛███▜▌   MiCode v1.0.0           ← 仅 1 行，Logo 上 2/3 未渲染
───────────────────────────────     ← 上边框（重复出现两条）
───────────────────────────────
(约 5 行空白)
[Hook] Session started at ...       ← Hook 位置偏下，远离 Logo
(约 20 行空白)
───────────────────────────────
❯                                   ← 输入框远在终端底部
───────────────────────────────
build │ mimo-v2-5-pro │ ...
```

**问题分解**：

| # | 现象 | 判断 |
|---|---|---|
| 1 | Logo 仅显示底部 1/3（1 行），完整 ASCII art 应有多行 | Logo 绘制被截断，或上部行被后续元素覆盖/超出可见区域起点 |
| 2 | 出现两条重复 border | 存在重复渲染：两组件各自绘制 border，或上帧残留 |
| 3 | Hook 与 Logo 之间隔了一条 border + 数行空白 | Hook 定位异常，未紧跟 Logo |
| 4 | Hook → 输入框间约 20 行空白 | Footer 使用固定底部定位（`position: absolute` 或 flex `marginTop: 'auto'`），未跟随内容流 |
| 5 | 输入框 → 状态栏紧贴 | 状态栏相对位置正常，问题在整体布局结构 |

**可能涉及的文件/函数**：
- Logo 组件 / 渲染函数（多行 ASCII art 的输出逻辑，是否被截断或偏移）
- 主布局组件（Logo → Hook → Border → 消息区 → Input → StatusBar 的纵向排列顺序及间距）
- Footer / Input 组件定位方式（需移除固定底部定位，回归文档流）
- Border 组件渲染调用点（排查重复绘制源）
- 外层容器的 `flexDirection` / `justifyContent` / `height` 配置
